# Company Risk Analysis

## Purpose

识别公司特定风险及传导路径。

## Invocation Match

用于首次覆盖风险、反证和监控问题，由 Workflow 选择并独立执行。

## Typical Intents

- 首次覆盖风险、反证和监控问题。

## Inputs

公司事实、行业竞争证据、财务与治理材料、asOf。材料仅限已获取正文；每项包含 sourceCandidateId 及 paragraph 位置。

## Produces

中文 answer、markdown、fact/inference/assumption findings 及其证据位置、limitations、risks、完成状态。

## Methodology

按经营、技术、竞争、财务、治理、政策梳理公司特定风险；逐项写触发条件、影响路径、可监控指标和缓解因素；给出最强反证和结论失效条件；避免泛泛宏观风险列表。

引用并购或购买价分摊表时，逐列核对被购买方表头、单位行和金额行。正数商誉与负数廉价购买收益可能属于不同标的；不得跨列套用符号或将负数解释移到另一家公司。若并购金额构成风险判断，应明确实体、期间、会计项目和影响路径。

年报如提供“商誉原值”“商誉减值准备”或资产组表，必须核对表头、单位、标的行和减值行；把已披露的商誉账面金额、减值变化及预测假设纳入风险矩阵，并说明资产价值、利润和现金流的传导。不同标的的正向商誉和负数廉价购买收益不可混写。不要把在本次研究材料中已出现的年报附注称为缺失；只对实际未提供的表、列或影响金额注明具体限制。

表格变动列中的负号代表来源披露的负值。若将负数改写成正数幅度，句子必须明确表述“减少/下降/回落”，并准确写明对应标的、科目和期间；不得将负数解释为增加或无方向金额。若无法区分期初、增加、减少、处置、其他变动及期末余额，应删除该变动数值并说明口径缺口，不得把同一行其他列的正数挪作该项变化。

若年报或半年报片段已披露实际控制人兼任董事长/总经理、内控体系/内控评价或关联交易决策制度，应把这些安排作为公司披露的缓释背景纳入风险矩阵；只将制衡效果、具体审议与回避执行、继任安排或执行成效列为尚待验证事项。不能因某一摘要未带该片段就断言本次材料没有相关治理披露；引用必须来自本方法实际收到的原文片段。

只报告材料明确披露的商誉余额、当期减值损失或资产组金额。不得自行用商誉原值减减值准备推算账面净额，或把余额变化推定为当期损失；除非 Workflow 提供了带来源、期间和单位的确定性计算结果。没有该结果时，描述已披露项目并说明金额口径限制，不补算净额。

只有当本次输入的证据片段确实包含对应会计政策或标的行时，才解释商誉或廉价购买的会计处理。段落定位必须从同一来源 ID 的已提供证据中原样复制；如果片段未包含所需原文，就删除一般会计说明，不得根据整份报告或记忆猜测段落编号。
每条定位必须按“文档标题 + sourceCandidateId + paragraph”成对核对。不同年度报告或中报即使存在相同段落号、相似商誉表或相同金额，也不得互换来源 ID；重试时须重新扫描全部引用，逐一核对材料标题与定位。

风险矩阵使用可读的 Markdown 表格，每个正文行的单元格数必须与表头列数一致。风险名称与触发条件、经营或财务影响路径、监控信号、缓解因素与残余风险按对应表头分别填写；不得把后三项揉进同一单元格并让其他列为空。单元格内需要文字分隔时用分号，避免未转义的竖线破坏列数。

## Evidence Requirements

关键事实引用准确来源位置；不以搜索摘要、模型记忆或典型行业惯例代替公司证据。保留来源时间、范围及冲突。

## Deterministic / Model Boundary

模型解释已提供证据；代码校验输入、引用和输出合同。Skill 不调用外部接口、不写入 KB、不调用其他 Skill；Workflow 管理采集、重试和组合。

## Missing Data

保留已有证据支持的部分分析。说明缺失输入、需要获取的材料和结论影响；核心问题未回答时标记 insufficient_evidence。

## Validation / QC

关键论点必须在 findings 中并绑定精确来源位置。判断、事实和假设分开；答案解释因果和反证。仅格式完整不代表研究完成。
风险矩阵的每一行都是风险传导记录：风险、触发条件与影响路径、监控指标、缓解因素及残余风险均需填入对应列；完成状态同时返回非空 risks 列表，且每项来自有来源引用的矩阵行。
