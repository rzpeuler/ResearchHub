# Research 首页会话布局与审核入口重排实施计划

依据：[已确认设计](../specs/2026-10-05-research-home-chat-layout-and-review-relocation-design.md)。本计划限于客户端布局与路由归属；不改图谱、知识内容、Pi 会话存储或后端路由。

1. 核对当前 Git、Research/Reviews 组件和样式优先级，保留未跟踪 `workspace/`。
2. 移除 Research 顶部每日情报卡片；将三个主题审核组件迁至 Reviews，并使 ReviewCase 的只读标记仅作用于该分区。保持框架运行 ID 和聊天草稿由 App 状态管理，进入 Reviews 时刷新现有审核数据。
3. Research 右栏改成基于现有会话、队列和 Workflow 状态的简明监控；审核仅保留跳转入口。相关 Workflow 完成时给出到 Reviews 的轻量入口。
4. 为三栏设置视口高度与独立滚动；中栏消息滚动，标题和输入区始终可见；输入区控件、摘要、输入框、附件及页脚统一深色主题和内容宽度。保证窄屏输入不被挤出视口。
5. 更新客户端测试：Research 不出现每日情报/主题审核，Reviews 显示对应分区，路由切换保留草稿，审核按钮可达；验证 CSS 的滚动和控件样式以及响应式规则。
6. 执行前端类型检查、测试和构建；用本地浏览器检查桌面与窄屏布局。检查差异及 Git 状态，只提交任务文件；抓取远端确认快进后推送。记录未完成的真实外部调用验证和仓库全量测试边界。

分工：一名 Luna 高推理子代理负责 `client/src/App.tsx` 与相应测试；另一名 Luna 高推理子代理负责 `client/src/styles.css` 的布局和外观。主代理负责跨文件整合、设计边界、最终验证与 Git 交付。并行修改时各自保留其他人的更改。
