# 设置、模型接入与知识库管理实施计划

依据：[确认的设计规格](../specs/2026-10-05-settings-model-connections-and-knowledge-management-design.md)。范围仅限应用配置、侧栏和弹窗；不修改图谱、Knowledge 内容或生产流程。

1. 记录当前 Git 与测试基线，保留 `workspace/` 用户数据。核对现有设置 API、Pi `ModelRuntime` 认证接口及知识库目录校验。
2. 前端：固定侧栏；设置菜单采用不占布局的定位层；新增居中模型接入与知识库管理弹窗；移除侧栏知识库选择。补齐语言、焦点、键盘及窄屏行为。
3. 模型后端：封装 Pi 支持的 OAuth 与 API Key 连接操作、非秘密状态与刷新；持久化受限的兼容端点模型定义并注册到 Pi；只在明确请求时测试外部连接。WorkBuddy 与 Claude Code 订阅按规格显示说明和限制。
4. 知识库后端：持久化登记目录，复用 manifest 和存储边界检查；提供目录验证、登记、刷新和移除；普通挂载继续只接受服务端 ID。拒绝链接、重复 ID、越界与运行中切换。
5. 整合服务端路由与客户端 API，统一设置变更互斥、错误脱敏、配置失败回滚以及模型/知识库状态刷新。保留当前全局模型与挂载的持久化语义。
6. 运行有针对性的服务端和客户端测试、类型检查与构建；在本地浏览器检查侧栏滚动和弹层位置。外部认证没有真实凭据时，只报告离线验证结果。
7. 检查最终 diff、修复回归、更新使用说明，提交并在确认远端快进后推送。明确报告未实调的外部提供商。

并行所有权：前端子代理负责 `client/src/`；模型子代理负责独立模型连接模块及其测试；知识库子代理负责独立登记模块及其测试。主代理负责共享的 `app/runtime/server.ts`、`app/runtime/application-runtime.ts`、跨模块整合、最终验证及 Git 交付。各代理不得覆盖其他代理编辑。
