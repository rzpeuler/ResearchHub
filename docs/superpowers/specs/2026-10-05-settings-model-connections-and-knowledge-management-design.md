# 设置弹层、模型接入与知识库管理设计

日期：2026-10-05
状态：设计已获用户口头确认，待书面规格复核
范围：React Client、Application Runtime 配置接口与 Pi 模型连接；不改变 Knowledge Graph 数据、投影或 Knowledge 生产逻辑。

## 1. 目标与既有边界

延续 [2026-10-04 侧栏与全局选择设计](2026-10-04-application-sidebar-model-and-knowledge-selection-design.md) 的单一全局模型：Pi 对话及所有 Workflow 语义调用仍使用同一个 `provider/modelId`。本次增加模型的接入配置，并把知识库的发现、登记、选择、取消挂载全部集中到设置弹窗。左侧栏底部保留全局模型选择和设置按钮，不再出现知识库选择控件。本规格取代旧规格中“侧栏底部知识库选择”和“客户端不提交任何路径”的界面与配置约束；普通挂载仍只接收服务端知识库 ID。设置配置不写 canonical Knowledge，不改变图谱。

保持单 Node 进程、直接嵌入 Pi SDK、React/Vite、HTTP JSON + SSE。Pi `ModelRuntime` 继续拥有模型目录与认证；Workflow 拥有执行控制；前端只通过受保护的 Application Runtime API 处理配置。用户通过配置界面输入目录或密钥时，服务端负责验证和保存，浏览器不直接读写本地文件或 Knowledge。

## 2. 界面与交互

侧栏固定在视口左侧，主内容独立滚动。侧栏内容过高时只滚动侧栏内部，底部操作仍可访问；展开、折叠及窄屏布局均保持右侧内容不被覆盖。设置按钮点击后，在按钮上方覆盖显示轻量菜单，不参与侧栏布局，也不移动模型选择、设置按钮或其他导航入口。菜单包含“中文”“English”“模型接入”“知识库管理”；语言按钮单击即切换并持久保存偏好。

点击“模型接入”或“知识库管理”后关闭小菜单，打开有标题、关闭按钮和明确焦点管理的居中大弹窗。弹窗支持 Esc、背景点击关闭、键盘操作及窄屏滚动；异步提交期间阻止误关和重复提交，失败时保留输入及原配置。关闭后焦点返回设置按钮。选择弹窗内部的不同视图不改变全站导航位置。

模型弹窗展示当前连接状态、可用模型数及三种路径：受支持的订阅登录、提供商 API Key、兼容 API 地址。完成连接后刷新 Pi 候选目录并显示可用或不可用原因；不会自动改变全局选择。侧栏仍承担频繁的模型切换。知识库弹窗展示当前挂载、候选库、版本与修订、发现目录和验证结果；在这里登记目录、刷新列表、挂载其他库或取消挂载。侧栏运行状态可显示“已挂载/未挂载”，但没有知识库选择操作。

## 3. 模型接入

### 3.1 内置提供商

服务端只列出当前 Pi SDK 实际支持的提供商及认证方式。Codex/ChatGPT 订阅入口使用 Pi 支持的 `openai-codex` OAuth 流程，浏览器展示授权地址、设备码或人工输入步骤，并通过短生命周期的服务端登录会话接收状态；服务端调用 `ModelRuntime.login`，凭据进入 Pi 的 `auth.json`。不得复用或复制 Codex CLI 的本地令牌文件，不得在界面宣称订阅必然可用。认证成功后重新检查目录与模型能力。

API Key 入口支持 Pi 内置提供商的密钥登录。密钥仅通过现有本地 Runtime token、Origin/CSRF 保护的请求送到服务端，由 Pi 凭据存储保存；应用设置文件、浏览器本地存储、响应、日志和错误信息均不保存或回显密钥。服务端只返回提供商、认证方式、连接状态和可选模型等非秘密元数据。注销或替换认证要明确显示对当前模型可用性的影响，并拒绝运行中可能改变认证来源的操作。

Claude Code 订阅的说明与 Claude API Key 分开。[Anthropic 当前说明](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)建议第三方应用采用 API Key；因此本应用不把 Claude Code 自身的登录状态当成 ResearchHub 可用的认证，也不承诺订阅额度可用于本应用。若未来 Pi 的 Claude OAuth 流程和提供商规则均允许且实际验证通过，可再开启相应订阅入口；当前可执行路径为 Claude API Key。WorkBuddy 展示为独立智能体服务的接入说明，当前不作为 Pi 模型或全局模型候选；其 [Open API](https://open.workbuddy.cn/docs/openapi) 不等同于 Pi 的模型推理接口。各卡片明确显示“可接入”“需要 API Key”或“不支持作为全局模型”的状态。

### 3.2 兼容 API 地址

用户可登记一个支持 Pi 已知协议的端点，填写名称、唯一 provider ID、模型 ID、协议类型、基础 URL、上下文窗口、最大输出 token 和 API Key。仅接受 HTTPS 地址或明确的本机 loopback HTTP；拒绝 URL 凭据、片段、重定向到不允许的地址、未支持协议及重复 ID。普通自定义端点不允许任意请求头、命令型密钥或可执行配置。服务端把非秘密模型定义持久化到应用私有配置，在构建 Pi `ModelRuntime` 时注册；密钥由 Pi 的凭据存储按 provider ID 单独保存。保存前验证字段及 Pi 模型结构，保存后刷新目录；只有文本与工具调用能力符合现有全局选择合同且认证可用的模型才能被选用。连接检查失败保留原全局模型，显示失败原因而不泄露端点凭据。

API Key 与兼容地址配置均不自动触发外部付费模型请求。用户明确点击“测试连接”时才发出最小的受限请求，界面说明该操作可能产生提供商费用；不以仅有凭据或目录项作为实调成功的证明。

## 4. 知识库管理

默认继续扫描项目同级 `ResearchHubData/knowledge-bases` 的直接子目录，并尊重现有配置的发现目录。弹窗允许用户输入本机绝对目录以登记一个已有 Knowledge Base，服务端只读取验证所需的目录元数据与 manifest：真实路径、非链接目录、Schema 0.3/0.4、Storage Format 1、合法 ID、Workspace 隔离和 ID 唯一性。验证失败应返回可操作的原因。浏览器不能可靠取得可信的本机绝对路径，故以明确的路径输入及示例引导，不伪装成浏览器文件夹选择器。

登记信息保存在应用私有配置中，重启后仍可发现；原本目录扫描和显式环境变量挂载保持兼容。配置 API 可以接收待登记路径，但普通挂载 API 仍仅接受服务端发出的知识库 ID。对已登记项可移除“登记”；这只移除目录索引，不删除任何知识库文件。当前挂载库须先取消挂载或切换，才能移除登记。所有路径只留在服务端配置和验证流程中，普通列表响应仅返回 ID、状态、Schema、修订与用于识别的非敏感标签。

挂载、切换与取消挂载沿用现有运行时重建与冲突检查：活跃对话、工作流或后台操作期间拒绝；失败保留原挂载；成功后清理旧库前端投影并重新读取 bootstrap。配置目录不创建、迁移或编辑 Knowledge Base。未来如果增加知识库创建、删除或内容维护，应另立任务并遵守 Knowledge Production 权限边界。

## 5. API 与失败语义

`GET /api/settings` 扩充非秘密连接状态和知识库登记/发现摘要。新增受相同本地 token、Origin 和 CSRF 规则保护的配置操作，分别处理模型认证开始/状态/提交/取消、API Key 保存或注销、兼容模型登记、知识库目录验证/登记/移除/刷新；现有模型选择及知识库挂载接口继续作为唯一生效切换入口。所有改变当前认证、候选目录或挂载的操作使用配置变更互斥和活跃任务检查。登录会话有到期和取消机制；窗口关闭不会留下可继续写入的无主会话。

输入错误返回 `invalid_input`，认证或模型能力不足返回明确不可用状态，并发或活跃运行返回 `conflict`，服务端存储与重建失败返回 `failed`。新配置采用原子替换；失败时不改变当前模型和挂载。所有错误在弹窗内可见，且不会包含 API Key、OAuth 令牌、授权回调参数或任意本机路径。

## 6. 验收

1. 右侧各页面滚动时侧栏固定；小菜单位于设置按钮上方且其他控件不移动。键盘、Esc、焦点恢复、窄屏与中英文单击切换可用。
2. 侧栏无知识库选择；知识库登记、刷新、挂载、取消挂载和移除登记均在设置弹窗中完成。已挂载项重启后保持，移除登记不删除源数据。
3. 内置 Pi 认证与 API Key 接入只向前端返回非秘密状态；新增候选经现有能力与认证检查后才可全局选用。OAuth 取消、过期、失败及配置冲突可恢复。Claude Code 与 WorkBuddy 的界面不错误宣称可用订阅模型。
4. 兼容端点拒绝危险 URL、重复 ID 与不支持协议；未授权不进行付费实调。配置失败保留原全局模型，显式连接测试有可见结果。
5. 目录逃逸、链接目录、Workspace 重叠、非法或重复 manifest 均被拒绝；知识库切换后旧库数据不继续显示。图谱数据与逻辑未改。
6. 类型检查、相关服务端与客户端测试、构建通过；本机 UI 检查侧栏固定和弹层位置。没有可用外部认证时，把真实 OAuth/API 调用记录为未验证，不用离线测试代替。
