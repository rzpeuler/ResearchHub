# 应用侧栏、统一模型与知识库挂载选择设计

日期：2026-10-04  
状态：用户已确认实施  
范围：Application Runtime 与 React Client；Knowledge Graph 的数据、投影和交互逻辑不变

## 1. 目标与架构边界

将全站主导航从顶部移至左侧。侧栏底部集中放置设置、中英文界面切换、全局模型选择和当前挂载知识库的选择。模型选择必须决定该本地应用中 Pi 对话和全部 Workflow 语义调用的同一个 `provider/modelId`，不允许固定模型的工作流绕过选择。知识库选择必须在前端可操作、重启后仍生效，并保持一次只挂载一个 Knowledge Base。

沿用单 Node 进程、直接嵌入 Pi SDK、React/Vite、HTTP JSON + SSE。Pi `ModelRuntime` 负责 provider、模型和认证；Workflow 继续掌握确定性执行，Knowledge 继续经既有生产通路写入。前端不得直接读写本地路径或 canonical Knowledge。本任务不补齐 AI 算力主题的产业或公司数据，也不修改图谱投影。

## 2. 界面

桌面端左侧是固定宽度应用侧栏：顶部品牌，中部现有八个入口，底部为“模型”“知识库”“设置”三个操作。设置面板包含中文和 English，沿用浏览器本地保存的语言偏好。模型区域显示当前模型的 provider 与名称、可选模型、不可用原因和切换失败消息；知识库区域显示当前库名称、版本与修订、可选库和挂载状态。移动导航后研究页原有对话列表仍是独立次级栏，其他页面使用侧栏右侧内容区。窄屏侧栏可折叠，主导航和底部操作仍可通过键盘访问。

模型或知识库切换完成后，客户端重新读取 bootstrap 与当前页面数据，撤销旧请求并清理旧库的主题、报告、审核、工作流和对话投影状态。切换中禁用重复提交；活跃请求不能被默默改绑到新配置。

## 3. 唯一模型选择

Runtime 保存唯一的 `provider/modelId`，由 Pi 的模型目录枚举候选、检查认证及语义输出能力。切换前验证目标模型；不可用时显示原因，保留旧模型。`gpt-6-luna` 必须出现在支持它的 Pi 版本目录中；升级 Pi 依赖并验证 API 兼容性。没有相应 Pi 认证时，它可以显示为待认证，但不能假装可调用。

Pi 对话的当前会话、新会话和恢复的旧会话都强制使用已选模型。所有 Workflow 语义执行器共享该模型；现有行业、主题框架和原始文档预览的固定 `codex exec` 模型路径改为 Pi SDK 调用，不再按工作流固定为不同模型。保留每条工作流现有的超时、输出大小界限、结构化输出合同及业务验证。对要求结构化结果的操作，必须使用已验证的提供方约束或等效严格校验；若模型不能满足，切换前拒绝该模型。生成失败不自动回退到另一模型。

选择保存于应用自己的本地运行数据，而非修改 Pi 的全局默认设置。重启时先读取已保存选择；首次启动可使用现有默认值。显式注入模型或执行器的测试与离线调用保持可控，但生产 Runtime 不允许不同工作流覆盖全局选择。运行中的对话或工作流阻止切换，避免一次执行跨两个模型。

## 4. 知识库发现与挂载

服务端从配置的知识库目录枚举直接子目录；本地默认目录为项目同级 `ResearchHubData/knowledge-bases`，并允许环境变量配置。列表只包含 manifest 可读、Schema 0.3 或 0.4 且 Storage Format 1 的库。当前由环境变量指定的合法库也可列出。客户端仅提交服务端发出的知识库标识，不提交任意路径。服务端对真实路径、目录包含关系和 Workspace 边界再验证，不跟随目录联接逃逸目录范围。

选择另一个库或明确取消挂载时，服务端先拒绝活跃对话、工作流和后台操作；然后重新建立绑定 Knowledge Service、生产服务、Pi 工具、Attachment Service 与会话的 Application Runtime。切换失败应恢复原挂载，向用户报告错误。成功后保存选择到本地运行数据；重启优先恢复这一选择，原有 `RESEARCHHUB_KNOWLEDGE_BASE_ROOT` 仅作为首次启动缺省值。关闭旧 Runtime 前必须解决运行中请求，SSE 订阅重新绑定；客户端丢弃旧库状态。取消挂载后自由研究仍可用，依赖 KB 的功能按现有 `no_kb_mounted` 语义提示。

知识库切换只改变运行时挂载，不执行任何 canonical 写入、迁移或图谱变更。

## 5. HTTP 合同与失败语义

新增受现有本地 Runtime token、Origin 和 CSRF 规则保护的配置接口：读取当前模型、模型候选及知识库候选；提交模型选择；提交知识库选择或取消挂载。响应包含实际生效的模型和知识库标识，以及可用于客户端刷新状态的配置修订。无效标识返回 `invalid_input`，缺认证或不支持的模型返回明确不可用错误，运行中或并发切换返回 `conflict`，重建失败返回 `failed` 并保留或恢复旧配置。配置文件采用原子替换，禁止把认证信息、任意本地路径或模型响应正文返回浏览器。

## 6. 验收

1. 桌面与窄屏均能通过左侧主导航到达现有全部页面；底部设置可切换中英文并保留偏好。
2. 选择可用模型后，当前、恢复和新建 Pi 会话，以及行业、主题框架、原始文档预览和其他 Workflow 语义执行都记录同一个 `provider/modelId`；不再存在生产默认的固定 CLI 模型调用。`gpt-6-luna` 出现在目录中，并按实际认证状态正确启用或禁用。
3. 未认证、结构化输出不兼容、模型不存在、运行中以及并发切换均给出可见失败；已选配置和正在执行的调用保持一致。结构化结果仍通过现有合同和验证器。
4. 从前端选择不同的可挂载 KB，页面与 Pi 工具读取新库；重启后保持选择；取消挂载后显示明确未挂载状态。拒绝目录逃逸和 Workspace 重叠。旧库数据不在新库页面短暂显示。
5. 类型检查、相关 Node 与客户端测试、客户端构建通过；用本机可用的真实 KB 验证挂载切换。外部模型实调如因认证不可用，应如实标记为未验证，不以夹具测试冒充。
