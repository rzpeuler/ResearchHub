# Theme Framework 与 Knowledge Graph 主题工作台设计

日期：2026-10-02
状态：产品设计已确认，待书面规格复核
范围：Theme 初始化与范围维护、研究知识写入契约、Knowledge Graph 主题展示

## 1. 目标与既有边界

用户能够仅凭名称建立一个 InvestmentTheme，经有证据的广度研究形成尽量完整、边界明确的产业网络；随后持续上传资料和运行产业、公司研究，将有价值的知识写入同一全局 Knowledge Base，并在一个主题窗口阅读持续更新的产业全景、公司信息、核心观点和时间链。

本规格修订 `docs/superpowers/specs/2026-09-28-knowledge-graph-topic-workspace-design.md` 的产品布局与主题内容组织。旧规格中关于 canonical 只读投影、真实关系方向、分页与修订绑定、来源权利和错误状态的约束继续适用；其中“中栏图谱、右栏 Inspector”和泛化分类阅读导航由本规格的主题工作台取代。单对象详情仍可通过现有只读接口读取，但不占据常驻右栏。

遵守现有架构：Theme 是全局知识图谱上的语义覆盖；Workflow 控制执行、获取资料与人工关口；Skill 负责专业语义判断；Gateway／Resolution／Validation／Writer 掌握 canonical 写入；前端不直接修改 Knowledge。不得创建第二份 Theme 专属知识库、独立 ThemeFramework canonical 图、通用 Agent Runtime 或新的编排层。

## 2. 已确定的产品规则

1. Theme 的名称必填，`themeGroupRef` 必填但可由系统使用默认组。定义与纳入／排除条件可以稍后补齐。ThemeGroup 可新增、编辑和移动 Theme；删除非空组前须选择目标组并批量迁移 Theme。移动组只更新 Theme 的组引用，不改知识对象的 Theme 关系。
2. 一个知识对象可以平等地服务多个 Theme，不设置主 Theme。用户上传资料不必指定 Theme，Theme 初始化也不依赖首次上传。
3. 上传时选中的 Theme 是 Workflow 的研究上下文，不将整份 Source 或其中全部提取候选自动标记为 Theme 知识。通过筛选、证据校验和治理后获准写入的内容进入全局 KB；其真实主语和来源不变。只有显式针对 Theme 的知识或经已确认行业／公司关系可达的知识，才进入相应主题展示。
4. 待验证动态和写入建议由未来与 Knowledge Graph 并列的 Daily Intelligence 窗口承接；其筛选与自动写入策略另行设计。Knowledge Graph 只展示已持久化的 canonical Knowledge 和从中生成的可追溯只读投影。

## 3. Theme Framework 的职责与拓扑

### 3.1 Skill 与 Workflow

新增独立的 Theme Framework Skill，输出 Theme 定义与范围建议、产业节点和关系候选、边界判断、证据及缺口。它不创建 canonical ID，不操作 Gateway／Writer，也不直接调度其他 Skill。Theme Framework Construction Workflow 读取已有 KB，按研究目标使用已配置的获取能力进行有界广度研究，并调用 Skill 判断框架；无需对每个节点自动运行完整产业或公司深度研究。用户可在框架建立后选择节点发起深度研究。

Skill 不以固定跳数决定边界。它结合与主题需求／资本开支的关系、经济或技术依赖、对供给／成本／壁垒／竞争判断的重要性、可独立研究价值、直接证据和继续上溯的边际研究收益，逐个判断。上下游关系成立与该节点值得纳入 Theme 是两项独立结论。比如电子布可以是 PCB 的真实上游，但未必应进入 AI 算力 Theme；消费电子可以是存储的真实下游，却因本 Theme 研究目标而排除。

图谱节点以**可独立研究的产业环节**为统一粒度。产品、技术和细分品类优先属于该环节的产业信息；若需要改变节点粒度，应审视相邻环节的一致性，不自动把单一分支拆得过细。一个 Industry 可有多个上下游和交叉连接；基础设施服务等与 Theme 相关的独立节点可以没有通向主链的 `upstream_of` 边。不得为树形布局虚构关系。

### 3.2 范围决策与持久化

每个候选节点和候选连接独立给出 `include`、`exclude` 或 `pending` 建议，并附理由、可用证据、缺口和受影响的分支。证据不足或研究价值难定的候选默认 `pending`；首次确认可以只建立已确认的网络，待处理项保留并在 Chat 反馈。明确排除的候选不因资料再次提及而反复提示；只有足以改变原判断的新证据才形成重开提案。

需要持久、版本化的 Theme 范围决策记录，至少包含 Theme ref、候选 Industry／Relation ref；尚未成为 canonical 对象的候选则使用跨运行稳定的语义指纹。记录还包含节点／连接类别、决定、理由、证据引用、建议与人工确认状态、确认时间、所依据的 KB revision、前版本引用以及重开依据。这属于 Knowledge 治理记录，不是第二份 canonical 产业图。确认纳入的 Industry 通过 canonical `theme_exposure` 表达；行业间关系仍是全局可复用的 canonical `upstream_of` 等 Relation。主题投影使用已确认的节点和连接选择，不能仅因全局关系可遍历就把边界之外的节点或连接带入主题图谱。

一次人工接受涉及的治理决定与 canonical ChangeSet 必须按同一 KB revision 校验，并以原子提交或可幂等恢复的协议落地；不得向读投影暴露“范围已确认、关系尚未写入”或相反的半成品。

如果候选行业或关系尚无足够证据成为 canonical 对象，它可以保留在待处理治理记录中，但不得进入正式图谱。Theme 排除不删除全局行业事实，也不影响其他 Theme 的关联。

### 3.3 人工确认与更新

首次候选网络在 Chat 中按分支展示，支持批量确认及逐项调整节点／连接的纳入、排除、待处理状态。界面必须展示被截断的研究范围、边界理由、证据和待处理项。确认后由 Workflow 将获准的变更送入既有 Knowledge Production 路径。

相关资料或研究结果完成 canonical 写入后，Workflow 依据变化的对象和关联 ref 先定位可能受影响的 Theme，再自动做有界范围影响检查，不遍历所有 Theme。一般事实更新不触发 Theme 人工审核；只有可能新增／移除主题节点、改变连接或重开既有排除决定时，才在 Chat 提出差异和证据。人工接受后变更生效；拒绝与待处理决定保留，用于后续去重与重查。不得因每次资料写入重跑整条产业链深度研究。

## 4. 资料、研究报告与 canonical Knowledge

用户在首页 Chat 输入处粘贴或拖入受支持文件，可手动选择写入，Agent 也可识别意图；必要的范围与定义问题由 Agent 在写入前后提出。资料可在没有 Theme 的情况下写入全局 KB。上传流程保留 Source／Raw 追溯、提取候选、筛选、冲突处理与人工 Review；“有证据”是写入必要条件，不代表所有客观事实都值得写入。详细知识筛选及自动写入政策不在本规格定型。

产业和公司研究工作流的报告是生成时点的研究快照。Skill 可保留自由叙述和有价值的非表格分析，但供主题窗口持续展示的事实、观点、指标、事件及关系必须走严格的知识写入流程。报告章节文本不会直接粘贴到 Graph 窗口，也不会因为上传时存在 Theme 上下文而批量改写知识的 canonical 主语。语义不确定或 Schema 尚无法表达的内容按研究缺口／报告材料保留，不伪造 canonical 结构。

Schema 0.4 是本设计的目标读写契约。当前原始资料写入与主题读取之间的版本、Source 和 proposal 能力缺口要在实施首阶段显式关闭；不对旧 KB 做未经验证的静默迁移。已有 0.3 KB 保持原样并得到明确的不兼容状态；需要在 0.4 使用其中资料时，从保留的原始文件经新版写入流程重新入库，原始文件不可用则明确报告缺口，不伪装为成功迁移。从空环境初始化时应能创建和挂载适用的 KB 及默认 ThemeGroup，再完成真实资料的端到端验收。

## 5. 竞争格局表与展示投影

行业研究 Skill 的 `competitive_landscape` 模块新增一个紧凑表格输出，用一张表说明该行业玩家的规模、基础业务和差异。每表选择 4–7 列，其中公司名称、主要产品、最新可核实市值及最新年报年度营收为优先基础字段；其余维度由 Skill 根据行业格局决定，可涉及份额、壁垒、关键技术、产能或客户等。缺值不能推断填充；市值标明交易日，营收标明财年和币种，可比性不足时明确说明。每行绑定 canonical Company 及其与当前 Industry 的可核实业务关联；非空单元格绑定相应 canonical Claim／Observation／Relation 等对象及其证据，Module 只组织表格，不另造一份事实。表头、行和单元格结构使用受约束的 `schemaId` 契约，而非任意 JSON。该表经 Gateway／Validation／Writer 成为目标 Industry 的 `competition` Module。当前生产提案契约没有 Module kind，需要补齐这条写入通路。

产业信息参考现有行业研究的八个模块，公司信息参考现有公司研究的十九个章节；它们是**阅读组织方式**，不要求把每段报告叙述变成僵硬的 Schema 字段。后端按 canonical 对象、关系和必要的模块引用生成有界主题只读投影。在知识修订后可运行受限的语义归类、排序与核心观点挑选，并保存其来源 ref、依据的 KB revision 和生成状态；前端打开或切换节点时不调用 LLM。旧 revision 的投影不得冒充最新知识。一个知识项可在多个阅读章节被引用，但列表与计数应去重，并避免不必要的重复展示。

核心观点默认展示最重要且与当前选择相关的三条判断，支持展开更多；不要求只能人工标记。时间链同时容纳已发生事件和未来可能的催化剂，不显示 KB 写入流水。历史事件优先使用发生日，未来催化剂标明预计日期及其不确定性；发生日未知而使用资料发布日期排序时，明确标注“资料发布日期”。

## 6. Knowledge Graph 窗口

桌面布局：左侧 ThemeGroup／Theme 目录；右侧内容区顶部是一张横跨原中、右两栏的行业图谱；图谱下方中列为产业信息及公司信息，右列为核心观点及时间链。所有分区同时存在，整页向下滚动。窄屏按目录、图谱、产业、公司、观点、时间链的顺序重排。图谱只显示行业节点，不显示公司节点、Theme 节点或 Claim／Source 节点。交叉关系和独立节点均需可读，不按树形强制排布。当前图的节点与边均来自确认范围内的 canonical 对象及关系，保持原方向；截断、空结果和范围限制要明确标示。

首次打开 Theme 时默认选中按 `importance` 与稳定 ref 顺序排列的第一个已确认行业；若无行业则各分区显示明确空状态。点击行业节点：产业信息和竞争格局表切换到该行业；公司信息切换到该行业上次浏览的公司，首次进入时取表中第一家，表为空时显示无公司记录；右侧观点和时间链跟随该行业。点击竞争格局表中的公司名：公司信息与右侧内容跟随该公司，图谱行业选择保持不变。右侧始终跟随最近一次点击的行业或公司。切换 Theme 时清理上一 Theme 的选择与过期请求，不能短暂显示旧主题内容。

空章节可折叠并标示无已写入知识；缺少证据、不可比较、资料不可用、权限受限、投影截断、KB revision 已变化是不同状态。图谱和内容读取必须受服务端范围／体积界限约束，必要时分页；Source／Raw 引用在后端可追溯，但本版窗口不额外设计资料卡或原文区，也不向页面泄露受限原文与本地路径。

## 7. 验收场景与阶段

必须用真实可挂载的 Schema 0.4 KB 做至少以下端到端验收，并辅以确定性隔离测试：

1. 从空环境只输入“AI 算力”名称，创建默认组下的 Theme；通过既有 KB 和可用渠道提出广度框架，展示候选、边界理由、来源和覆盖缺口。
2. 框架包含真实交叉关系、一个独立基础设施节点、明确排除的消费电子分支及证据不足的待处理节点；首次确认后仅纳入获准节点和连接，待处理不阻断 Theme 创建。
3. 不指定 Theme 上传资料，合格知识可进入全局 KB；指定 Theme 上下文也不使整份资料的所有知识自动成为 Theme 成员；同一知识可在多个 Theme 中平等呈现。
4. 产业／公司研究完成后，报告快照与 canonical 写入结果可区分；Graph 展示更新后的产业与公司章节、4–7 列竞争格局表、核心观点、历史事件及未来催化剂。
5. 点击行业和公司时各分区按规则联动；全局上游关系不会越过已确认 Theme 边界扩张节点；图的交叉与独立节点均可阅读。
6. 新证据触发有界影响检查；既有排除决定不会因重复资料反复出现，足以改变结论时进入人工确认；确认前图谱不改变。Revision 变化、缺证据、来源不可用和访问限制均有可辨状态。

建议按独立可验收的工程阶段推进，每阶段再形成细化实施计划：

1. Schema 0.4 写入基础及治理契约：可用的空 KB 初始化、研究到知识的共用写入通路、Theme 范围决策、Competition Module proposal／校验／Writer。
2. Theme Framework Skill、Construction Workflow 和 Chat 人工确认；先闭环名称创建与首张产业网络。
3. 产业／公司研究知识更新及 revision 绑定的主题展示投影。
4. `/graph` 三栏工作台改造及真实 KB 端到端视觉、交互验收。
5. 新知识写入后的 Theme 范围影响检查与人工变更闭环。

本规格不包含 Daily Intelligence 的独立窗口、候选动态写入政策、全行业定期深度重研、自动创建 Theme、完整报告原文在 Graph 的展示或任意无界产业遍历。
