## Current requirement and consumer audit

The repository has the generic `IndustryDomainDataRequirement` materializer in `data/requirements.ts`. The canonical Skill catalog (`app/services/research-skill-catalog.ts`) declares five optional, generic `DOMAIN` templates for `industry_supply_demand_cycle`: supply/capacity, demand, inventory, pricing, and utilization. However, the production Industry invocation does not call `DataResolver.resolveSkillRequirements` for these templates; the matching/resolution behavior is currently exercised only by Data foundation tests. Therefore none of the five current D4 metric keys is wired through that Skill invocation. The current direct D4 observation path routes parsed observations only to Industry Research's `market_size_growth` and `supply_demand_analysis` modules. Preserve the existing generic templates and cycle methodology; do not infer capacity, utilization, inventory, or demand from output, trade, or price.

The Catalog has no registered identity aliases or metric definitions for these five keys. Their current Data lifecycle is therefore `DISCOVERED_ONLY` (outside the Catalog); this is an audit classification, not a persisted Catalog lifecycle transition. Candidate semantic roles/families and final candidate classifications are given per row above.

## Parser and provider defects observed

1. **MIIT paired-price misbinding:** the official 2026 H1 article says carbonate `16.3` and hydroxide (micropowder grade) `15.3`; the parser emitted `16.3` for both. This is a false numeric value, not just missing qualification. Hydroxide H1 is rejected until source-to-field mapping is corrected and independently verified.
2. **Acceptance timestamp drift:** the real acceptance script hard-codes `now`/`asOf` to 2026-09-23. Its report says `generatedAt` is that date even when run on 2026-10-08. Update the acceptance harness to distinguish actual retrieval/run time from its explicit PIT cutoff.
3. **Generic Industry evidence coverage:** direct composition attempts on 2026-10-08 yielded no documents for MIIT, Gov.cn, or CPCA for either target. Eastmoney returned one air-conditioner board-membership snapshot (533-character payload), which is not an operating observation and has no publication-time history. Eastmoney discovery failed for lithium. These outcomes are availability/probe facts, not evidence that those source families never publish relevant material.
4. **Catalog gap:** the Data Industry Catalog currently requires canonical definitions and attached source policies for resolver use, but has no production mapping for the audited identities and no separate stable aliases, source-field selectors, product/grade qualifiers, value-version contract, or source-revision identity. No D4 metric is currently canonical in Data.

## Existing path and migration boundary

- Generic Industry documents currently flow from `ResearchService` through `IndustryAcquisitionComposition` and its MIIT, Gov.cn, Eastmoney, CPCA, and optional AKShare adapters. `ResearchService` supplies those normalized documents to the Industry Workflow acquisition waves.
- Structured NBS, MIIT, and CHEAA observations are fetched, parsed, merged, and PIT-qualified by `plugins/research-acquisition/industry-operating-observations.ts`. Workflow and Skill import this Plugin-owned observation contract directly. The runtime separately constructs this path.
- `data/industry-catalog.ts`, `data/requirements.ts`, and `data/resolver.ts` already provide catalog lifecycle, semantic DOMAIN requirement materialization, canonical-only industry matching, and policy-bound acquisition. Runtime does not yet route either Industry path through that resolver.
- The existing observation merger preserves disagreeing rows and emits a conflict diagnostic; it does not average. Current parser mappings still require field-by-field correction before any source can be treated as accepted numeric truth.
- Existing Skill modules remain the right home for interpretation. Workflow should retain acquisition-wave sequencing, requirement context, evidence-to-module mapping, report generation, and the governed Knowledge Gateway path. Provider I/O and source-specific parsing remain Plugin responsibilities.

## Design review proposal

Recommended migration boundary for review:

1. Keep acquisition and source-specific parsing in Plugins; move the provider-neutral observation contracts, field identity/quality validation, and conflict/availability types under `data/`.
2. Govern explicit Industry identities and source policies in the Industry Data Catalog. Use distinct metrics for each product/grade, physical quantity/value, period aggregation, geography, and source authority. Do not promote a source or identity solely because it was discovered or fetched.
3. Route generic Industry evidence and typed operating observations through per-run `DataResolver` factories assembled by `ResearchService`/Runtime. Workflow materializes target, module, period, and `asOf` requirements; Skill receives only resolved, source-bound evidence/data.
4. Preserve the existing normal report and Knowledge Gateway/Writer behavior. Keep unsupported metrics as explicit gaps and retain current direct-acquisition seams only as compatibility fixtures during migration, then remove them when call sites are migrated.
5. Treat the MIIT duplicate-price defect and acceptance timestamp drift as prerequisites to claiming a clean real-source acceptance. Re-run MIIT, NBS, and CHEAA plus generic provider attempts on the final normal path. Keep the result partial wherever value-version PIT, series history, scope, transport, or parser behavior fails.

This is a proposal only. No implementation or catalog promotion has been performed in this audit.
