# Project Overview

## 项目名称

ResearchHub

## 项目目标

建立一个可长期演进的研究型软件项目，并通过清晰的架构、可追踪的任务和可回溯的决策支持持续开发。

当前第一目标不是实现业务功能，而是建立工程执行状态管理体系，使后续 Agent 能脱离聊天上下文恢复项目状态并继续工作。

## 核心业务价值

当前已确认的核心价值是：将项目目标、工程状态、架构边界、决策依据和交付记录沉淀在仓库中，降低协作信息丢失和重复决策成本。

ResearchHub 面向的具体业务场景、业务对象和商业价值仍未冻结，后续应通过产品/架构决策逐步补充，不在本阶段虚构。

## 用户需求

### 当前已确认的工程用户需求

- 新 Agent 能仅通过仓库文档快速理解项目状态。
- 工程执行者能明确当前任务、边界、验收条件和同步要求。
- 架构决策能够被记录、追溯并避免重复讨论。
- 项目负责人能够依据文档和 Git 历史进行审查与验收。

### 尚待确认的产品用户需求

终端用户角色、核心工作流、功能优先级和成功指标尚未正式定义，列入后续产品发现与架构设计阶段。

## 当前阶段

**Phase 0 — Governance Bootstrap（工程治理初始化）**

仓库刚刚启动，当前没有业务代码、运行时服务、数据结构或 API 实现。

## 核心技术方向

当前已确定的技术基础只有：

- Markdown 文档作为项目治理状态的长期载体。
- Git 作为版本管理和变更回溯机制。
- GitHub 作为远程仓库和协作入口。

业务运行时技术栈、存储方案、服务边界、部署方式和外部服务尚未决策。后续技术选择必须记录在 [DECISION_LOG.md](DECISION_LOG.md) 并同步 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 长期愿景

在不牺牲架构清晰度和工程可维护性的前提下，逐步建设 ResearchHub 的实际研究业务能力，形成可扩展、可验证、可持续交接的产品与工程系统。

长期愿景的具体产品形态、用户范围和技术路线以未来已批准的产品及架构决策为准。
